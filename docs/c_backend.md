# C backend overview

The C backend compiles TinyLanguage programs into a small, self-contained C
runtime plus generated bytecode tables. It is intended for building native
executables or capturing generated C/LLVM output for inspection.

## When to use it

- **Native executables**: produce a standalone binary via `cc/clang/gcc`.
- **C/LLVM inspection**: emit C source, LLVM IR, or LLVM bitcode for debugging
  or performance experiments.
- **A/B behavior checks**: compare interpreter output with the compiled output
  for regression coverage.

## CLI entrypoints

Two entrypoints target the same backend:

- **`python -m tinyc_cli`**: convenience wrapper around the compiler CLI.
- **`python src/tiny_language_compiler_cli.py`**: direct CLI entrypoint (same
  flags, easier to inspect).

### Build a native executable

```bash
python -m tinyc_cli examples/c_backend/hello_world.tiny -o hello_world
```

### Emit generated C source

```bash
python -m tinyc_cli examples/c_backend/hello_world.tiny --emit-c > hello_world.c
```

### Emit LLVM IR or bitcode

```bash
python -m tinyc_cli examples/c_backend/hello_world.tiny --emit-llvm hello_world.ll
python -m tinyc_cli examples/c_backend/hello_world.tiny --emit-bc build/hello_world.bc
```

### Debug builds + custom compiler

```bash
python -m tinyc_cli examples/c_backend/hello_world.tiny -o hello_world --debug
TINYLANG_C_COMPILER=clang python -m tinyc_cli examples/c_backend/hello_world.tiny --emit-llvm hello_world.ll
```

## Supported feature set

The C backend shares the same feature subset as the LLVM pipeline. For the most
current feature matrix, see `docs/backend_feature_matrix.md`. If a construct is
unsupported it raises `NotImplementedError` during code generation so gaps stay
visible.

## Testing and stability checks

- `python -m pytest tests/test_c_backend.py -q` exercises the C backend when a
  compiler is available.
- `python -m pytest tests/test_tiny_language_compiler_cli.py -q` validates CLI
  behavior for the `--emit-c` path.
- Keep quick A/B checks handy: run once with the interpreter and once with
  `python -m tinyc_cli` to compare outputs for the same `.tiny` program.
