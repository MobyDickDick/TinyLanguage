# Upgrade guide: 1.0.0 → 1.1.0

**Release date:** 2026-05-01 (planned minor-release checkpoint)
**Scope:** Minor release upgrade guide for TinyLanguage 1.1.0.

## Summary

This guide captures the release-candidate migration workflow for the first minor upgrade. It documents what is automated today, what remains manual, and how to validate a 1.0.0 → 1.1.0 rollout before promoting the release.

## Automated migrations

Run the migration tool (dry run first):

```bash
python tools/release/prepare_minor_upgrade.py \
  --from 1.0.0 --to 1.1.0 \
  --apply --dry-run
```

Planned automated steps:

- No mechanical migration edits are required for 1.1.0. Keep `prepare_minor_upgrade.py` in dry-run mode to emit the guide/checklist artifact and validate recipe integrity.

## Manual migration steps

- Review release notes for any API or CLI changes introduced in 1.1.0.
- Run the full test suite after upgrading to confirm behavior matches 1.0.0 expectations.
- Update any automation or documentation references if the release introduced renamed commands.

## Validation checklist

- Run the project test suite and linting workflow.
- Verify TinyLanguage CLI commands in automation and CI.
- Confirm package/module imports resolve correctly.


## Recommended validation commands

Run these commands from the repository root after upgrading in a clean environment:

```bash
python tools/release/prepare_minor_upgrade.py --from 1.0.0 --to 1.1.0 --apply --dry-run
python -m pytest tests/test_tiny_language_cli.py tests/test_tiny_language_compiler_cli.py
python -m pytest tests/test_spec_conformance.py
python tools/check_format_lint.py
```

Record command output in the release notes or RC checklist so the migration verification is auditable.

## Rollback plan

- Revert the migration commit.
- Pin TinyLanguage tooling to 1.0.0 until the blockers are resolved.
